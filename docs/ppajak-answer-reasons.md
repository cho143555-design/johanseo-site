# 빠작 2권 풀이 근거 기록

## 적용 범위

- 2027 빠작 중학 문학 독해 2
- 2027 빠작 중학 비문학 독해 2

다른 교재의 입력 방식, 정답 데이터, 교재 배정 및 기존 제출 기록은 변경하지 않는다.

## 학생 화면

첫 제출은 각 문항에 선택 이유를 짧게 적는다. 오답 재풀이에서는 처음 쓴 근거를 보여주고, 처음 잘못 생각한 점과 현재 선택의 근거를 각각 받는다. 빈칸과 공백만 있는 입력은 허용하지 않으며, 최소 글자 수를 채우도록 강제하지 않는다. 과도한 입력을 막는 상한은 항목당 1000자다.

재풀이를 저장해도 처음 제출한 답과 근거는 덮어쓰지 않는다. 교재의 실제 문항 번호를 유지하며, 기본 개념처럼 번호가 불연속인 세트도 지원한다.

학생의 초안과 재풀이 연결 정보는 현재 브라우저 탭의 sessionStorage에 보관한다. 다른 기기나 새로운 브라우저 세션에서 이전 재풀이를 자동으로 이어가는 기능은 포함하지 않는다. 서버에 제출된 기록은 이와 별도로 보존된다.

## 관리자 확인

관리자 페이지의 수업 기록 → 풀이 근거 확인 — 첫 제출과 오답 재풀이에서 조회한다. 이름 필터는 등록명과 정확히 일치하는 이름을 사용한다. 처음 근거, 재풀이에서 적은 오해, 바뀐 근거를 함께 읽을 수 있다.

선택 이유의 타당성을 자동 채점하는 기능은 아니다. 객관식 답이 정답이어도 근거가 타당한지는 별도로 확인해야 한다. 자유 서술 근거는 기존 Discord 알림에 추가 전송하지 않는다.

## 저장 및 검증

- submissions.reasoning: 제출 회차별 근거, 최초 근거, 직전 근거, 이전 제출 연결 정보를 담는 JSONB.
- submissions.reasoning_request_id: 동일 요청의 중복 저장 방지를 위한 UUID.
- 기존 행은 새 컬럼이 NULL이며, 기존 기록을 채우거나 다시 채점하지 않는다.
- 서버는 대상 교재, 실제 문항 번호, 재풀이 연결 대상과 직전 오답 목록, 필수 서술을 검증한다.
- 정답표와 service_role 키를 학생 브라우저로 전달하지 않는다.
- 새 조회 정책을 추가하지 않고 submissions의 기존 관리자 조회 정책을 사용한다.

## 배포 파일

- student-ui.js에서 student-reasons.js를 로드한다.
- admin-nav.js에서 admin-reasons.js를 로드한다.
- Supabase smooth-task에는 server/grade.ts와 server/reasoning-core.js를 함께 배포하고 verify_jwt=true를 유지한다.
- DB에는 server/add_submission_reasoning.sql을 한 번 적용한다.

## 회귀 검사

Node 22 이상에서 `node --test tests/reasoning.test.cjs`를 실행한다. 빈 근거 거절, 불연속 문항 번호, 재풀이 기록 보존, 중복 저장 방지, 기존 교재 채점 및 질문 제출을 검사한다. 실제 학생 이름으로 가짜 제출 기록을 만들지 않는다.

배포 후 학생 화면에서 두 교재에만 입력칸이 나타나는지, 관리자 조회가 가능한지 별도로 확인한다. 저장 테스트에 모의 데이터나 모의 서버를 쓴 경우 실제 운영 서버의 제출 검증과 혼동하지 않는다.

롤백 시에도 이미 제출된 근거 기록을 삭제하지 않는다. 프런트엔드와 smooth-task의 호환성을 함께 확인하며, 추가한 nullable 컬럼은 데이터 보존을 위해 남겨 둘 수 있다.
